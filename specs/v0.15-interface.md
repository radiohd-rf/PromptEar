# v0.15 — Интерфейс: две области, список файлов, лайв-трансляция

## Цель
Эволюция интерфейса v0.14 в полноценный «двухобластный» рабочий инструмент:
- слева — ввод и обслуживание (дропзона, количествo файлов, настройки, лог);
- справа — результат (список файлов + окно лайв-трансляции черновик → готовый результат);
- кнопка запуска переносится в правый верхний угол окна;
- полная управляемость процесса: кликабельный список файлов, копирование текста в любой момент, «Пропустить».

## 1. Раскладка окна (CSS-сетка)
```
┌────────────────────────────────────────────────────────────┐
│ Шапка: заголовок                      [▶ Запуск] в пр. углу │
├──────────────────────────┬─────────────────────────────────┤
│ ЛЕВАЯ ОБЛАСТЬ            │ ПРАВАЯ ОБЛАСТЬ                  │
│ дропзона                 │ список файлов (кликабельный)    │
│ строка «N файлов выбрано»│                                 │
│ настройки транскрибации  │ окно лайв-трансляции:           │
│   · формат               │   · черновик (поток)            │
│   · с обработкой / без   │   · готовый результат           │
│ окно лога                │   · [📋 Копировать] [⏭ Пропустить]│
└──────────────────────────┴─────────────────────────────────┘
```

### Левая область
- Дропзона: перенос/выбор файлов (как в v0.14).
- Ниже дропзоны — строка «Выбрано: N файлов».
- Настройки транскрибации:
  - **Формат**: DOCX / TXT / MD / SRT / VTT (уже реализовано в v0.14);
  - **Режим обработки** (три значения, подтверждено обсуждением):
    - «без» — только черновик Whisper, без кнопки «Улучшить с ИИ»;
    - «авто» — ИИ-улучшение сразу после транскрибации (`enhance_mode=auto`);
    - «спросить» — после транскрибации кнопка «Улучшить с ИИ» (`enhance_mode=ask`, сохраняется из v0.14).
- Окно лога (существующее `#log`).

### Правая область
- **Список файлов** — левая колонка правой области:
  - каждый файл (аудио/видео) со статусом: `обработано` / `в обработке` / `не обработано` / `пропущено`;
  - файлы с ненулевым статусом (обработано, в обработке, пропущено) — кликабельны;
  - клик переключает фокус окна лайв-трансляции на этот файл (если результат уже известен — показывается он; если файл только транскрибируется — активный поток);
  - пропущенные = «обработанные наполовину» (см. §2: кнопка «Пропустить»); при клике показывается частичный текст + бейдж «Пропущено», частичный файл сохраняется.
- **Окно лайв-трансляции** — правая колонка правой области:
  - показывает поток текста выбранного файла: по мере транскрибации текст появляется постепенно (по сегментам Whisper — порции-фразы; механизм `DraftEvent` уже есть);
  - после транскрибации начинается трёхуровневый прогон улучшения, видимый в этом же окне в **реальном времени по словам** (см. §3-стриминг);
  - кнопка **«Пропустить»** (`⏭`): останавливает транскрибацию текущего файла ИЛИ трёхуровневую обработку почти мгновенно; переключается на следующий файл (если их несколько) или останавливает (если файл был один);
  - кнопка **«Копировать»** (`📋`): копирует текст из окна в любой момент — даже во время транскрибации или обработки (копируется текущее состояние текста окна).

## 2. Логика «Пропустить»
- Применяется на любом шаге — транскрибация или улучшение — и **рвёт почти мгновенно** (подтверждено обсуждением).
- Транскрибация: прерывание на границе текущего чанка Whisper (~30 сек), частичный текст до текущего куска.
- Улучшение: при стриминге генерация обрывается немедленно (закрытие соединения к llama-server), текста-«обрывка» не мусолим — сохраняется текущий лучший результат (черновик или завершённые проходы).
- Действие:
  1. текущий файл помечается «пропущено» (обработан наполовину);
  2. результат на момент пропуска (частичный текст/черновик/лучший проход) сохраняется в выбранном формате (без гарантии качества);
  3. поток переключается на следующий файл в списке (статус → «в обработке»);
  4. если файл был единственным — обработка останавливается полностью (как текущий `cancel` + `done`).
- Реализация: вызвать существующий `cancel.set()` для текущей задачи? Нет — отмена глобальная. Правильнее: сигнал на уровне текущего файла (`skip`-флаг в per-file state), шаги пайплайна проверяют его между сегментами/проходами и завершают работу файла досрочно, после чего оркестратор переходит к следующему.

## 3. Режимы улучшения и стриминг по словам
- **Управление**: `enhance_mode` = "none" | "auto" | "ask" (в настройках левой области — выбор «без / авто / спросить»).
- **Стриминг генерации** (подтверждено обсуждением):
  - `_call_llm` переводится на `stream: True` (llama-server SSE);
  - токены собираются в батчи ~10 слов и шлются в UI событием `EnhancingStreamEvent(text_so_far)` — «модель печатает» улучшенный текст по мере генерации каждого прохода;
  - кнопка «Пропустить» во время генерации закрывает соединение к llama-server — проход обрывается почти мгновенно;
  - база для прерываемости: соединение requests с `stream=True` + флаг skip, проверяемый между чанками ответа.

## 7. Решения из обсуждения (зафиксировано)
- Стриминг ИИ-улучшения: **да, по словам** (`stream: True`, батчи ~10 слов).
- «Пропустить» посреди прохода LLM: **да, рвать соединение** к llama-server почти мгновенно.
- Режимы: **три** (без / авто / спросить).
- «Пропущенный» файл: **показывать частичный текст** + бейдж «Пропущено», сохранять частичный файл.
