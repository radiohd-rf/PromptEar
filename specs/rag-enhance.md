# Спека: RAG-справочник для улучшения понимания русского (этап улучшения)

Дата: 2026-09-22. Статус: согласовано, **реализация отложена** («потом»).

## 1. Цель

Повысить качество **улучшения** (gemma/llama-server) за счёт локального
справочника (глоссарии, доменные термины, правила русского), подаваемого в
промпты трёх проходов. Оморофоны, «не услышанные» Whisper (например
«обезьяны и какашки» → «обезьяньи какшки», см. MEMORY #29), gemma способна
исправить на этапе переписывания — **если модель получит знание о слове**.

Важно: RAG улучшает **только** улучшение. Транскрибация (Whisper/ctranslate2)
— это акустическая модель без промпт-входа; RAG к ней неприменим (доступен
только `hotwords`, который юзер уже отверг в #28/#29 — см. §9).

## 2. Текущее состояние

- `processing/enhancer.py`: `enhance_multi_pass()` — 3 прохода
  (`_pass_cleanup`/`_pass_style`/`_pass_structure`), каждый проход собирает
  свой промпт; `topic` детектится один раз (`detect_topic(text)`) и вставляется
  в каждый промпт строкой `\nТема: {topic}` — готовый «карман» для справки.
- Чанкирование: `_chunk_text(text, ENHANCER_CHUNK_SIZE)`; каждый чанк проходит
  все 3 прохода независимо.
- Стриминг через `_call_llm_stream`; таймкод-правило `TS_KEEP_RULE` добавляется
  при `keep_timestamps`.
- Движок SAGE: не развиваем (MEMORY), RAG касается только llama.

## 3. Что входит в справочник (RAG-корпус)

Локальная папка `models/rag/` (создаётся при старте; вне git, в `models/`):

- **Пользовательские глоссарии** — файлы `.md`/`.txt`, которые юзер кладёт
  сам (или «Создать глоссарий» из UI). Формат — как им удобно, ретривер
  разбивает на абзацы/строки.
- **Вшитый статичный справочник русского** — `models/rag/_ru-rules.md`
  (или в репозитории `assets/rag/ru-rules.md`, копируется при первом запуске):
  краткие правила орфографии/согласования, список частых спорных слов.
  Даёт gemma «внешнюю память» по русскому без её знания.
- **Примеры исправлений (опц., этап 2)** — автодобавление пар «ошибка→правильно»
  из реально исправленных пользователем фрагментов (см. #29).

Ограничение корпуса (защита от «мусорного RAG»): только текстовые файлы,
максимум общий размер (config), `._`/скрытые игнорируются.

## 4. Ретривер

### Этап 1 (рекомендован): лексический ретривер — без ML-зависимостей
- Индексация при старте: чтение файлов, разбивка на чанки (абзац/строка),
  построение инвертированного индекса по лексемам (lowercase, без стоп-слов).
- Поиск: по `topic` + ключевым существительным/именам/числам текста чанка;
  BM25-подобная близость (порядок 100 строк кода, без зависимостей).
- Требование к корпусу: он маленький (глоссарии юзера), поэтому лексика точнее
  и детерминированнее эмбеддингов, плюс нулевой риск поломки оффлайна.
- Помечаем ряд «точных» совпадений (термин встречается в чанке дословно) —
  их можно подавать с флагом «точное».

### Этап 2 (опционально, если корпус разрастётся): эмбеддинги
- Офлайн-модель конкатенации (multilingual-e5-small / BGE-m3 ~100–200 МБ) через
  `sentence-transformers`; индекс-кэш `models/rag/.index.json` (перестроение по
  mtime).
- Включается только при `RAG_EMBEDDINGS=1`; по умолчанию этап 1.

## 5. Инжекция в промпты

В каждый из трёх `_pass_*` после правил/`topic`, перед `\n\nТекст:`:

```
Справочная информация (может содержать точные термины:
  - <fragment 1>
  - <fragment 2>
Используй её ТОЛЬКО если она релевантна и подтверждает исправление.
Если слово/термин не совпадает по контексту — НЕ применяй, оставь как есть.
Сомневаешься — оставь текст без изменения.
```

- Контекст: не более `RAG_MAX_CONTEXT_CHARS` (по умолчанию ~1200 симв., ~300
  токенов) — не раздувает промпт и не затягивает генерацию.
- Инструкция всегда подчёркивает минимальные изменения — уже свойство проходов;
  справка лишь снимает часть «сомнений».
- `TS_KEEP_RULE` не трогаем: справка идёт отдельным блоком, метки не упоминает.

Вызов ретрива:
- Один раз на всё улучшение: `retrieve(query_topic + первые N существ. чанка)`.
- Для длинных текстов (этап 2) — дополнительно один ретрив на группу чанков.

## 6. Модуль и API

Новый `processing/rag.py` (рядышком с enhancer):

```python
class RagEngine:
    def __init__(self, root: Path): ...  # root = models/rag
    def rebuild_index(self) -> None: ...  # при старте / изменении файлов
    def retrieve(self, query: str, top_k: int = 5) -> list[dict]:
        ...
        # [{"text": str, "score": float, "exact": bool}]

    @property
    def enabled(self) -> bool: ...  # False, если корпус пуст
```

- `LlamaCppEnhancer` получает опциональный `rag: RagEngine | None` (фабрика
  `create_enhancer()` в web/server.py создаёт один на процесс; кеш в модуле).
- Загрузка ленивая; если корпус пуст / модель не обязательна — `enabled=False`
  и промпты не меняются вовсе (нулевой оверхед).
- Повторная индексация: по mtime при каждом старте приложения (дёшево для
  маленького корпуса) + кнопка «Обновить справочник» в настройках.

## 9. Не-цель (границы)

- **НЕ** влияет на транскрибацию (Whisper). `hotwords`/словарь для транскрибации
  отклонены юзером ранее (#28/#29) — RAG это НЕ возрождает; словарь-корректировка
  живёт на этапе улучшения.
- **НЕ** облачные эмбеддинги/API — всё офлайн.
- **НЕ** автосбор корпуса из интернета. Спектр: только глоссарии юзера + вшитые
  правила + (опц.) его же исправленные тексты.
- **НЕ** меняет SAGE-движок.
- Оморофоны, которые gemma не сможет исправить даже с контекстом, остаются
  как есть (модель 2B — потолок ограничен; справка лишь добавляет факты).

## 10. Критерии приёмки

1. Тест-кейс #29: глоссарий с «какшки» → после улучшения
   «обезьяны и какашки» → «обезьяньи какшки» (проверить после реализации).
2. Пустой `models/rag/` или выключенный чекбокс → промпты идентичны текущим
   (сравнить до/после — байт-в-байт сборка промпта не меняется).
3. Неверная справка не портит текст: глоссарий с заведомо нерелевантной
   записью → результат улучшения не деградирует (инструкция «оставь как есть»).
4. `_result_too_short` по-прежнему защищает (справка не сокращает текст).
5. Оффлайн: при отсутствии сети RAG работает (всё локально), апдейт корпуса —
   ручной.
6. Регресс: тайм-коды, перевод, стриминг, skip, улучшение в ручном режиме —
   без изменений (11-api.md / 05-processing.md).
